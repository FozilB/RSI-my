# Market Structure Scanner (OKX)

Сканер публичных рыночных данных OKX для всех активных USDT perpetual swap инструментов. Сразу после закрытия каждой 30m-свечи (в :01 и :31 UTC) он анализирует закрытые свечи 30m, а 1h и 4h — сразу после закрытия их свечей, и присылает Telegram сообщение только после последовательности медвежьего подтверждения: CHoCH → LH → BOS → ретест.

Сканер только читает публичные данные. Торговых ордеров, ключей OKX и функций торговли нет.

## Архитектура

- GitHub Actions запускает `scanner.py` цепочкой без VPS: каждый запуск сам ставит следующий и досыпает до ближайшего :01/:31 UTC. Расписание (`11,41 * * * *`) — только резерв: на практике GitHub выполнял часовой cron раз в ~8 часов.
- `scanner.py` получает список `*-USDT-SWAP` из публичного API OKX и свечи OHLCV.
- `structure.py` находит подтверждённые swing high/low, классифицирует HH/HL/LH/LL и проверяет последовательность подтверждения.
- `state/state.json` сохраняет обработанные свечи, отправленные сигналы и ожидающие отправки уведомления. Actions cache переносит его между запусками.
- Telegram получает сообщение только для полностью подтверждённого сигнала. При сбое отправки сообщение остаётся в очереди на следующую попытку.

## Правила структуры

1. Swing high/low подтверждается, если его экстремум выше/ниже заданного числа соседних свечей слева и справа. Поэтому pivot становится известен только после закрытия правых свечей.
2. HH/HL и LH/LL сравнивают последовательные подтверждённые swing high и swing low.
3. Медвежий CHoCH — закрытие ниже последнего swing low после структуры HH + HL.
4. После CHoCH цена формирует промежуточный swing low, затем LH ниже последнего HH.
5. Медвежий BOS — закрытие ниже промежуточного swing low после LH.
6. Ретест — последующая закрытая свеча касается уровня BOS в пределах допуска, заданного через ATR, и закрывается ниже уровня. Уведомление появляется только на этой свече.

7. Схема сбрасывается, если она сломалась или устарела: после CHoCH цена закрылась выше прежнего HH, после LH цена закрылась выше LH, со времени CHoCH прошло больше `SETUP_MAX_BARS` свечей или ретеста нет дольше `RETEST_MAX_BARS` свечей после BOS. Так бот не шлёт сигналы по отменившемуся развороту и не «застревает», пропуская следующую схему.

Параметры pivot, ATR-допуск и список таймфреймов находятся в `config.py`. Это формализованная версия рыночной структуры, а не единственное общепринятое определение.

## План сделки в сообщении

В каждом сигнале есть подсказка для шорта (бот сам ордера не ставит):

- **Вход** — закрытие свечи ретеста.
- **Стоп-лосс** — чуть выше LH (нижнего максимума), на `SL_BUFFER_PCT` процентов.
- **Тейк 1** — прибыль, равная риску (`TP1_R`): закрыть половину и перенести стоп в точку входа.
- **Тейк 2** — прибыль в два риска (`TP2_R`): закрыть остаток.
- **Объём позиции** — посчитан так, чтобы при срабатывании стопа потеря была `RISK_USDT`.
- Если цена уже ушла вниз больше чем на `MAX_CHASE_R` риска, вход не догонять. При стопе шире `MAX_RISK_PCT` процентов приходит предупреждение.

Все числа меняются в `config.py`, выключается блок строкой `TRADE_PLAN = False`.

## Настройка GitHub

1. Откройте **Settings → Secrets and variables → Actions** и добавьте:
   - `TELEGRAM_BOT_TOKEN` — токен от @BotFather;
   - `TELEGRAM_CHAT_ID` — ID чата, куда бот может писать.
2. В **Actions** включите workflows, если GitHub попросит.
3. Запустите **Market Structure Scan → Run workflow** с `dry_run=true`, чтобы увидеть сообщения в журнале без отправки.
4. Для проверки Telegram запустите workflow с `test_telegram=true`.
5. Цепочка стартует сама с ближайшим резервным запуском по расписанию, либо запустите **Run workflow** без галочек один раз вручную.

Секреты OKX не требуются. Не добавляйте токен Telegram в файлы репозитория.

## Состояние и дедупликация

Для каждого инструмента и таймфрейма сохраняется время последней обработанной закрытой свечи. Это позволяет часовому запуску обработать обе новые свечи 30m, закрывшиеся с прошлого запуска. Ключ сигнала включает инструмент, таймфрейм и время свечи ретеста. Успешно отправленные ключи хранятся 30 дней. Неотправленные уведомления остаются в очереди состояния и повторяются при следующем запуске.

GitHub Actions cache — best-effort хранилище: одновременные запуски ограничены concurrency, но кэш может быть удалён GitHub или недоступен. При пустом состоянии сканер не рассылает старые сигналы из истории: первый запуск рассматривает только ретест на последней закрытой свече каждого инструмента/таймфрейма.

## Свежесть сигналов

- Сигнал отправляется, только если с закрытия свечи ретеста прошло не больше `MAX_SIGNAL_AGE_MIN` (25) минут. Более старые пишутся в журнал как `Skip stale` и не отправляются — даже если запуск был пропущен.
- В сообщении есть строка «Сейчас: цена (% от входа) · сигналу N мин».
- Если цена уже ушла ниже зоны «не догонять» или выше стопа, сигнал не отправляется (`SKIP_IF_CHASE`).
- Неотправленные из-за сбоя Telegram сообщения тоже выбрасываются, если устарели.

## Ограничения

- Если GitHub задержит или оборвёт цепочку, сигналы за это время пропадут (лучше пропустить, чем прислать поздно). Цепочку восстанавливает резервное расписание.
- Время закрытия сигнала позже фактического закрытия свечи из-за правых свечей для подтверждения pivot, загрузки всех инструментов и расписания Actions.
- У API OKX бывают ошибки, лимиты и временные сбои. Ошибки отдельного инструмента логируются, последующие инструменты продолжают обрабатываться.
- Новый или малоликвидный инструмент может иметь недостаточно свечей для структуры.
- Алгоритм ищет только медвежий разворот по согласованной последовательности. Он не оценивает фундаментальные факторы и не гарантирует исход движения.
- Это информационный сканер, не финансовая рекомендация и не торговый бот. План сделки в сообщении — подсказка уровней, а не гарантия результата.

## Локальный запуск и тесты

```bash
python -m pip install -r requirements.txt
python scanner.py --dry-run
python -m unittest discover -s tests -v
```

## Файлы

- `scanner.py` — OKX, очередь Telegram, состояние и цикл сканирования.
- `structure.py` — swing points и алгоритм CHoCH/LH/BOS/retest.
- `config.py` — параметры алгоритма.
- `.github/workflows/scan.yml` — цепочка запусков GitHub Actions каждые 30 минут.
- `tests/` — unit-тесты структуры, плана сделки и фильтров свежести.
